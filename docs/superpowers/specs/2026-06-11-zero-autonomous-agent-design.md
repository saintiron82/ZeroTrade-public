# Winner-1 (구명 Zero) — 완전 자율 트레이딩 에이전트 설계

## 목적

가이드 없이 **AI 판단만으로** 움직이는 자율 트레이딩 에이전트를 추가한다.
룰 파일·전략 지시·청산 파라미터를 일절 주지 않고, 종목 탐색부터 진입·청산·타이밍·자기 도구 제작까지 전부 에이전트가 결정한다.

부수 가치: 룰 기반 가이드를 받는 mirinae 계열과 같은 파이프에서 운용되므로,
**"가이드가 실제로 성과에 기여하는가"를 audit 데이터로 검증하는 대조 실험**이 된다.

## 결정 사항 (사용자 확정)

| 항목 | 결정 |
|------|------|
| 자율 경계 | 판단 전부 자유 + **시스템 하드 가드만 유지** (예산, 일일손실 한도, 파생ETF 토글, audit 기록 — 계좌 보호 차원) |
| 배치 | strat-001 합류 — winner-1 30%(9만원) / mirinae-3 70%(21만원) |
| 판단 방식 | **도구 자율 탐색** — AI가 읽기 전용 도구를 직접 골라 호출하며 스스로 탐색 |
| 종목 범위 | 국내 전 종목 (KOSPI·KOSDAQ 주식 + ETF 전체, 파생ETF 토글 OFF 적용) |
| 런타임 도구 | **에이전트가 필요한 도구를 런타임에 직접 작성·실행·축적·재사용** |
| 아키텍처 | A안 — Claude Code CLI 에이전틱 세션 + 도구 작업장 |

## 봇 정체성

- bot_id: `winner-1`, 파일 `src/bots/winner1.py`
- **BotBase 직접 상속** — MirinaeBot의 포지션 리뷰 루틴·청산 로직 같은 구조적 가이드를 물려받지 않는다
- 레지스트리 등록 + `BotUISpec` 정의 (파이프 UI 표시 의무)

## 에이전트 세션 구조

매 스캔마다 agentcli(Claude provider)로 CLI 세션을 연다. `conversation_id="bot:winner-1"`로 대화를 이어가 이전 판단의 맥락(자기 연속성)을 유지한다.

### 시스템 프롬프트 — 전략 지시 0

포함하는 것 (물리적 사실만):
- 정체성: "너는 실전 계좌의 자율 트레이더다. 가용 예산 {budget}원. 목표는 수익 극대화."
- 제약 고지: 주문은 최종 JSON으로만 가능 / 보유 잔고 내 매도만 가능 / 파생ETF(인버스·레버리지) 계좌 미신청 / 거래 시간 제약
- 작업장 안내: 위치, 자작 도구·journal 사용법, 작업장 밖 쓰기 금지
- 출력 스키마 (아래)

포함하지 않는 것: 진입/청산 규칙, 지표 추천, 종목 추천, 리스크 규칙, 페르소나 지시. 월스트리트 품질 기준(CLAUDE.md 3-1)도 **의도적으로 미주입** — 그것이 실험 변수다.

### 정보 접근 — 읽기 전용 MCP

전용 MCP 설정으로 읽기 도구만 노출:
- 시세/차트(일·분봉)/호가/투자자동향/순위(등락·거래량·ETF)/종목검색/뉴스/산업지수
- 자기 상태: 잔고, 자기 거래이력(`source='winner-1'`), 자기 판단이력
- **미노출**: buy_stock/sell_stock, 파이프·봇 제어, 설정 변경 — 주문 집행권은 봇 코드에만 있다

### 런타임 도구 작업장

`data/agent_workspace/winner-1/` — CLI 세션의 작업 디렉터리(cwd):
- `tools/` — 에이전트가 작성한 스크립트 (스크리너, 지표 계산기, 상관분석, 백테스트 등). 세션 간 영속, 재사용·개선 자유
- `journal.md` — 자기 전략 메모·복기 (자기 관리 기억; bot_state와 별개)
- 스크립트 실행은 venv 파이썬 사용 가능

샌드박스 한계 (명시): 스크립트는 동일 사용자 권한으로 실행되므로 OS 수준 격리가 아니다. 방어선은 (1) 주문 도구 미노출 (2) 프롬프트 제약(작업장 밖 쓰기 금지) (3) audit 기록(작업장 변경분 추적).

### 출력 스키마

```json
{
  "action": "buy" | "sell" | "hold",
  "code": "6자리 (buy/sell 시)",
  "qty": 0,
  "reason": "판단 근거",
  "next_scan_minutes": 30
}
```

- `next_scan_minutes`: **다음 판단 시각도 에이전트가 결정** — 5~240분 클램프, 장외엔 다음 개장까지 대기
- 세션 타임아웃 기본 10분 — 초과/파싱 실패/세션 오류 시 그 스캔은 hold 처리 + 오류 기록 (재시도 없음)

## 실행 경로

```
winner-1 스캔 → _audit_start_run() (BotBase 기존 구현)
  → CLI 세션 (도구 탐색 + 자작 스크립트 실행)
  → 판단 JSON 파싱
     ├─ buy/sell → engine.buy()/sell() — 하드 가드 체인
     │   (예산, 일일손실 -2%, 파생ETF 토글, KOSPI 급락 가드는 엔진 기본값 따름,
     │    KIS 실잔고 클램프)
     ├─ hold → 기록만
     └─ 실패 → hold 폴백 + 오류 기록
  → next_scan_minutes 반영
  → audit finish (ordered / blocked / completed / failed)
```

## 자율과 가드의 경계 (명시)

- **장 마감 강제 청산(MarketCloseGuard) 미적용** — 오버나잇 여부도 에이전트 판단
- **트레일링 스탑·손절 파라미터 없음** — 손실 관리는 전적으로 에이전트 책임. 시스템 개입은 일일손실 한도(-2%)와 예산 상한뿐
- **에볼버/Insight Engine은 winner-1의 파라미터를 조정하지 않는다** — 성과 비교 관찰 대상으로만 취급 (대조군 순수성 유지)
- 파생ETF 토글(전역) OFF 적용 — 계좌 능력 제약이지 가이드가 아님

## Audit (전 과정 투명)

- `ai_audit_logs`: 시스템 프롬프트 + 최종 응답 전문, 토큰, 소요시간
- `evidence_snapshots`: 판단 JSON, 세션 중 작업장 변경분(생성·수정된 도구 파일 목록), next_scan 결정
- `decision_runs` / `trades(source='winner-1')` / `decision_outcomes`: 기존 경로 그대로 — 대시보드·KPI에서 mirinae와 동일 기준 비교 가능

## 비용 통제

- 스캔당 CLI 세션 1회 (세션 내 도구 호출 다회) — 토큰은 기존 `_log_token_usage` 경로 기록
- next_scan 하한 5분 + 장중만 스캔으로 일일 호출 자연 상한
- KIS 읽기 호출은 기존 레이트 리미터(초당 18건) 적용

## 테스트

- 판단 JSON 파싱: 정상 / 불량 JSON / 필드 누락 / 비정상 action → hold 폴백
- next_scan_minutes 클램프 (5 미만, 240 초과, 누락, 음수)
- 가드 연동: 예산 초과 매수 차단, 파생ETF 차단 (엔진 가드 기존 테스트 패턴)
- 작업장: 첫 스캔 시 생성, tmp 경로 격리 테스트
- CLI 세션은 mock — 테스트에서 실 AI 호출·실거래 없음
- 가동 전 dry-run 1회 (실주문 없는 검증 모드)로 세션→파싱→기록 전 구간 확인

## 가동 절차

1. 구현 + 테스트 통과
2. `link_bot("strat-001", "winner-1", 0.3)` — mirinae-3 자동 70%로 재배분
3. **사용자 확인 후** 서버·파이프 재가동 (어제 머지된 보호 장치들도 이때 함께 적용됨)

## Out of Scope

- winner-1 전용 UI 페이지 (파이프 UI의 BotUISpec 표시로 충분; Agent Ops 대시보드가 Phase 2에서 커버)
- 멀티 에이전트 토론 구조 (mirinae의 방식 — winner-1은 단일 에이전트)
- OS 수준 샌드박스
- 미국 주식
